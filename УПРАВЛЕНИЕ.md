Дата: 17.09.2026. Короткая справка для оператора.

Всё управление — либо кнопками на GitHub, либо командами ниже. Лезть в код
для включения и выключения не нужно никогда.

## Рубильник рассылки — главный

Пока переменной `SEND_TO_B24` нет или она не равна `yes`, **в Битрикс24 не
уходит ничего**. Сводки собираются, лежат в очереди, видны в отчёте — но не
отправляются.

Включить постоянную рассылку:

```bash
gh variable set SEND_TO_B24 --repo dsxx1/cbr-regulatory-monitor --body "yes"
```

Выключить:

```bash
gh variable delete SEND_TO_B24 --repo dsxx1/cbr-regulatory-monitor
```

Отправить **один раз**, не включая постоянную: вкладка *Actions* → «Сводка
в Битрикс24» → **Run workflow** → галочка «Отправить в чат ОДИН раз».

## Выключить и включить отдельный процесс

Выключить мониторинг (перестанет ходить в ЦБ):

```bash
gh workflow disable "Мониторинг разъяснений ЦБ" --repo dsxx1/cbr-regulatory-monitor
```

Выключить сводку:

```bash
gh workflow disable "Сводка в Битрикс24" --repo dsxx1/cbr-regulatory-monitor
```

Включить обратно — та же команда со словом `enable`:

```bash
gh workflow enable "Сводка в Битрикс24" --repo dsxx1/cbr-regulatory-monitor
```

Посмотреть, что включено:

```bash
gh workflow list --repo dsxx1/cbr-regulatory-monitor --all
```

---

## Выключить модель, оставив обнаружение

Удалить ключ — система продолжит находить и фиксировать изменения, но перестанет
их разбирать. Ничего не сломается, в отчёте будет написано, что модель выключена.

```bash
gh secret delete LLM_API_KEY --repo dsxx1/cbr-regulatory-monitor
```

Ограничить расход, не выключая совсем:

```bash
gh variable set LLM_MAX_CALLS_PER_RUN --repo dsxx1/cbr-regulatory-monitor --body "3"
```

---

## Отозвать доступ к Битрикс24

Два независимых способа, любой достаточен.

**Со стороны GitHub** — удалить секрет:

```bash
gh secret delete B24_WEBHOOK --repo dsxx1/cbr-regulatory-monitor
```

**Со стороны портала** — удалить сам вебхук: Приложения → Разработчикам →
ваш вебхук → удалить. Так надёжнее: ссылка перестаёт работать отовсюду,
где бы её копия ни оказалась.

## Остановить всё разом

```bash
gh workflow disable "Мониторинг разъяснений ЦБ" --repo dsxx1/cbr-regulatory-monitor
gh workflow disable "Сводка в Битрикс24" --repo dsxx1/cbr-regulatory-monitor
gh workflow disable "Бот постановки задач из чата" --repo dsxx1/cbr-regulatory-monitor
```

Всё останется на месте, просто перестанет запускаться. Включается обратно
теми же командами с `enable`.

---

## Убрать насовсем

Удалить репозиторий — вместе с ним исчезают код, история, секреты и расписания.
Отдельно после этого имеет смысл удалить вебхук в Битрикс24 и ключ на OpenRouter,
чтобы не оставлять действующих доступов.

```bash
gh repo delete dsxx1/cbr-regulatory-monitor --yes
```

Локальные копии останутся в `C:\Projects\cbr-regulatory-monitor`
и `C:\ProjectSync\regulatory-monitor` — их удалять вручную.

## Куда смотреть

| Что нужно | Где |
|---|---|
| Работает ли вообще | https://github.com/dsxx1/cbr-regulatory-monitor/actions |
| Что нашёл последний прогон | там же, сводка на странице прогона |
| Полный отчёт | артефакт `otchet` внизу страницы прогона |
| Что стоит в очереди на отправку | `outbox.json` и `outbox-digest.json` в репозитории |
| Что уже отправлено | там же, поле `external_id` заполнено |

Прогон, упавший красным, письмом не оповещает — GitHub присылает уведомление
на почту владельца репозитория, если это не отключено в настройках аккаунта.

## Проверить, ничего не задев

Сводка без отправки: *Actions* → «Сводка в Битрикс24» → Run workflow,
галочку отправки **не** ставить.

Бот без создания задач: *Actions* → «Бот постановки задач из чата» →
Run workflow, галочка «Сухой прогон» стоит по умолчанию.

Список чатов портала: там же, галочка «Показать список чатов с номерами».
