# Исправление карточек, интерфейса и статусов

Визуальное направление: frontend-design-direction (ECC), уточнённое скриншотом пользователя FreeLLMAPI. Почти чёрный фон, тонкие границы, белая типографика и мятный акцент; без декоративных градиентов и яркого свечения.

Важность больше не вычисляется по словам заголовка. Без содержательного разбора — «Не оценено». После разбора обязательны статус события, краткая суть, влияние, сроки с оговорками, рекомендуемые действия, неизвестные обстоятельства и основания. Инициатива не превращается в действующее правило.

Пример СРО /1000018373.html: загружен полный текст, выполнены бесплатная генерация и отдельная модельная проверка. Ранние ошибочные варианты (неверные цитаты, представление обсуждаемого лимита как установленного) отклонены. Финальный вариант прошёл проверку; после неё редакционно уточнено, что отсутствие подтверждения в статье не доказывает отсутствия акта. Добавлена ссылка на официальный контекст ФПП и различение дат базового приказа и обсуждаемых поправок. API-квитанции сохранены; два финальных вызова cost=0.

Появились содержательный Markdown и скачиваемый статический файл. Для неразобранных карточек экспорт «разбора» недоступен, вместо пустого шаблона показывается причина.

Сбор коротких HTML-новостей теперь получает текст полной страницы перед анализом. Неподдерживаемые PDF и слишком длинные тексты не получают придуманной сводки. Такие материалы остаются на обработку, с явным статусом.

Источники: вместо «Ответил» — количество загруженных материалов или понятная ошибка, время последней проверки и имена разделов без числовых ID. Загрузка отделена от анализа.

GitHub Actions: точный отказ регистрации бота insufficient_scope — ожидаемая блокировка настройки, успешное завершение сбора с публичным статусом и summary, без ack сообщения. Другие API/сетевые ошибки остаются ошибками. Почтовые уведомления аккаунта не отключались; уже полученные письма не удалялись.

Новый режим workflow `status` проверяет доступность методов без отправки и без LLM, обновляет состояние доставки и публикует сайт. Используется для проверки исправления причины повторных Run failed.
