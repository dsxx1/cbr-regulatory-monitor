Дата: 16.09.2026.

# Часть 1. Главная развилка: файл или облако

Вы просили один txt вместо переменных окружения. Это можно, но есть жёсткое
условие, которое надо понимать до начала:

> **Файл с ключами работает только там, где этот файл физически лежит.
> GitHub Actions ваш диск не видит.**

Отсюда ровно два непересекающихся варианта. Третьего нет.

| | **А. Файл на своей машине** | **Б. Секреты на GitHub** |
|---|---|---|
| Где лежат ключи | `secrets.txt` рядом со скриптом | Settings → Secrets |
| Где крутится | ваша машина, планировщик Windows | GitHub Actions, бесплатно |
| Задержка бота | хоть каждые 2 минуты | 30–60 минут |
| Работает при выключенном ПК | только если это сервер | да, всегда |
| Как выбросить, когда надоест | удалить папку | удалить репозиторий |
| Что уже настроено | ничего | **всё, работает с 15.09** |

Код поддерживает оба: сначала смотрит `secrets.txt`, потом окружение.
Настраивать ничего не надо, просто положите файл — он подхватится.

**Моя рекомендация: вариант Б для мониторинга, вариант А — только если
захотите быстрый чат-бот.** Мониторингу задержка безразлична, а боту нет.

Про «сервис может стать не нужным скоро» — это как раз довод **за** GitHub,
а не против. Выбросить репозиторий это одна кнопка, и вместе с ним исчезают
все ключи разом. Файл на диске надо не забыть найти и удалить, а он к тому
моменту уже расползётся по бэкапам и синхронизациям.

# Часть 2. Где взять каждый ключ

## 2.1. Вебхук Битрикс24 — это и есть «пароль»

Отдельного пароля не будет. Вебхук — это ссылка, внутри которой уже зашит
номер сотрудника и секретный токен. Кто держит ссылку, тот действует от имени
этого сотрудника.

**Шаги:**

1. Откройте Битрикс24 под учётной записью сотрудника, **у которого есть доступ
   к нужному чату**. Вебхук наследует его права, не больше.
2. Слева внизу: **Приложения** → **Разработчикам**.
3. Выберите **Другое** → **Входящий вебхук**.
4. В списке прав отметьте **ровно два**:
   - **`im`** — чат: читать сообщения и писать в чат;
   - **`tasks`** — задачи: создавать.

   Больше не отмечайте. CRM, диск, телефония нам не нужны, а лишние права —
   это лишний ущерб, если ссылка утечёт.
5. Нажмите **Сохранить**. Появится ссылка вида:

   ```
   https://ваш-портал.bitrix24.ru/rest/12/x7k2m9p4q1w8e3r5/
   ```

   Скопируйте её целиком, вместе с завершающей косой чертой.

**Что делать, если утекла:** там же удалить вебхук и создать новый. Старая
ссылка сразу перестаёт работать. Это делается за минуту, поэтому не стесняйтесь
пересоздавать при любом сомнении.

## 2.2. Номер чата

Формат зависит от типа:

| Что | Формат | Пример |
|---|---|---|
| Обычный чат | `chat` + число | `chat1234` |
| Чат рабочей группы | `sg` + число | `sg17` |
| Личные сообщения | просто число | `12` |

**Как узнать:** откройте нужный чат в браузере и посмотрите на адресную строку —
номер будет в конце адреса. Если чата ещё нет, создайте новый и назовите
по-человечески, например «Регуляторные изменения».

## 2.3. Номер сотрудника

Нужен для двух вещей: на кого ставить задачи и кому разрешено командовать ботом.

Откройте профиль сотрудника в Битрикс24 — номер будет в адресе страницы,
вида `/company/personal/user/12/`. Число `12` и есть идентификатор.

Можно оставить пустым: тогда задача уйдёт на того, кто её попросил.

## 2.4. Ключ модели

Нужен только для анализа. Без него обнаружение работает, просто не будет
разбора требований.

**DeepSeek** — платно, но копейки: около 7 центов в месяц на нашем объёме.
Зайти на `platform.deepseek.com`, раздел **API keys**, создать ключ.
Пополнить баланс — минимальная сумма покрывает год работы.

**OpenRouter** — есть бесплатные модели. Зайти на `openrouter.ai`, раздел
**Keys**. Лимит бесплатных: 20 запросов в минуту и 50 в сутки — нам хватает
с большим запасом. Но политику обращения с данными бесплатных маршрутов
я подтвердить не смог, а в промпт уходит описание процессов компании.
Для пилота нормально, для постоянной работы лучше платный.

# Часть 3. Куда положить

## Вариант А: файл

1. Скопируйте `secrets.txt.example` в `secrets.txt` (в той же папке).
2. Заполните значения.
3. Всё.

Файл уже закрыт `.gitignore` — в репозиторий он не попадёт. Проверить можно так:

```bash
git check-ignore -v secrets.txt
```

Должно ответить, что файл игнорируется правилом. Если команда молчит — **не
коммитьте ничего**, пока не разберётесь: значит защита не сработала.

Код дополнительно проверяет это при каждом запуске и громко ругается в консоль,
если файл не прикрыт.

Формат простой, решётка начинает комментарий:

```
B24_WEBHOOK = https://портал.bitrix24.ru/rest/12/x7k2m9p4q1w8e3r5/
B24_CHAT_ID = chat1234
LLM_API_KEY = sk-...
```

## Вариант Б: GitHub

Значения с секретом — в **Secrets**, остальное в **Variables**
(*Settings → Secrets and variables → Actions*).

| Куда | Имя |
|---|---|
| Secrets | `B24_WEBHOOK`, `LLM_API_KEY` |
| Variables | `B24_CHAT_ID`, `B24_RESPONSIBLE_ID`, `B24_ALLOWED_AUTHORS`, `B24_COMMAND_PREFIX`, `LLM_BASE_URL`, `LLM_MODEL`, `SEND_TO_B24` |

Через командную строку значение не попадёт в историю команд:

```bash
gh secret set B24_WEBHOOK --repo dsxx1/cbr-regulatory-monitor
```

**Рубильник отправки** — переменная `SEND_TO_B24` со значением `yes`.
Пока её нет, сводки собираются, но наружу не уходят. Одного вебхука
недостаточно: включение — отдельное осознанное действие.

# Часть 4. Бот в чате

## Как он устроен

В Битрикс24 есть настоящие боты — через `imbot` и событие `ONIMBOTMESSAGEADD`.
Портал сам стучится на ваш адрес, реакция мгновенная. **Но для этого нужен
постоянно доступный извне адрес**, а у нас всё живёт на расписании, входящих
соединений никто не принимает.

Поэтому бот работает **опросом**: по расписанию читает чат методом
`im.dialog.messages.get`, берёт только сообщения новее курсора и разбирает их.

Плата за это — задержка. На GitHub реалистично 30–60 минут, локально — минуты.

## Как он не цепляет лишнего

Это ваш главный вопрос, и ответ на него я сделал сознательно скучным.

**Никакого распознавания намерений моделью.** Соблазн большой: пусть модель
поймёт, что человек просил задачу. Но живой рабочий чат для неё — сплошная
двусмысленность, и ошибаться она будет в обе стороны: наплодит задач из
обсуждений и пропустит прямую просьбу. Непредсказуемый бот в рабочем чате
раздражает быстрее, чем приносит пользу.

Вместо этого — **явная команда**. Сказал — получил, не сказал — ничего
не произошло.

Четыре рубежа:

1. **Один чат.** Читается только тот, что задан в `B24_CHAT_ID`.
2. **Префикс команды.** Сообщение обязано начинаться с `задача:`, `/задача`
   или `taskadd:`. Список настраивается.
3. **Белый список авторов.** Если `B24_ALLOWED_AUTHORS` заполнен — команды
   принимаются только от них. Пусто — от всех в чате.
4. **Курсор и однократность.** Каждое сообщение обрабатывается ровно один раз,
   даже если прогон повторится.

Плюс предохранители: не больше 5 задач за прогон, системные сообщения
игнорируются, свои же ответы бот не читает.

## Что ловится и что нет — проверено

| Сообщение | Результат |
|---|---|
| `задача: сверить форму 0420890 за сентябрь` | задача создана |
| `Задача: подготовить ответ в ЦБ` | задача создана |
| `/задача обновить регламент` | задача создана |
| `задача: проверить применимость` + вторая строка | задача, вторая строка в описание |
| `надо бы поставить задачу по отчётности` | **пропущено** |
| `коллеги, а задача по форме кто делает?` | **пропущено** |
| `давайте создадим задачу на проверку` | **пропущено** |
| `Задача была поставлена вчера` | **пропущено** |
| `задача:` без текста | **пропущено** |
| ответ самого бота | **пропущено** |

Пятнадцать случаев, все отработали верно.

## Как выглядит работа

```
Петров:  задача: сверить форму 0420890 за сентябрь
         Срок до пятницы, вопрос по графе 33

[бот]    Задача создана: сверить форму 0420890 за сентябрь (ID 4821)
```

Задача ставится от имени автора команды. Если задан `B24_RESPONSIBLE_ID` —
ответственным будет он, иначе сам автор.

## Проверить, ничего не создавая

```bash
python chat_watch.py --dry-run
```

Прочитает чат, покажет, какие задачи создал бы, и не создаст ни одной.
Первый запуск делайте именно так.

# Часть 5. Про минуты GitHub

Для приватного репозитория бесплатно 2000 минут в месяц, и **каждый запуск
округляется вверх до минуты**, даже если он длился 15 секунд.

| Частота опроса чата | Запусков в месяц | Расход |
|---|---|---|
| каждые 15 минут | ~2900 | **не влезает** |
| каждые 30 минут | ~1450 | влезает, но впритык |
| раз в час | ~720 | спокойно |

Мониторинг и сводка забирают ещё около 70 минут. Поэтому в расписание бота
поставлен **один раз в час** — так остаётся запас.

Если нужна реакция быстрее, есть два честных выхода:

- **сделать репозиторий публичным** — тогда минуты Actions не считаются вообще;
  секретов в коде нет, данные ЦБ и так открыты, но это ваше решение;
- **перенести бота на свою машину** с файлом `secrets.txt` и опросом раз
  в 2–5 минут.

Мониторинг при этом может спокойно остаться на GitHub. Разделить их — нормально.
